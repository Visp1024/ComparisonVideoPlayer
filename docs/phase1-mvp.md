# Фаза 1 — MVP одиночного плеера

Приложение `src/ComparisonPlayer` (.NET 9, WPF, x64) — первый рабочий плеер проекта:
открытие файла, покадровый транспорт, таймкод и номер кадра, шкала позиции, сведения о ролике.

Мокап, по которому собран интерфейс: [mockups/phase1-mvp-player.html](mockups/phase1-mvp-player.html).

## Что сделано

- **Каркас приложения**: `App` поднимает движок FlyleafLib до создания окна, настройки
  (`Settings`) лежат в `%APPDATA%\ComparisonVideoPlayer\settings.json`.
- **`IPlaybackBackend`** — интерфейс движка воспроизведения: `Open/Close`, `Play/Pause`,
  `StepForward/StepBack`, `SeekToFrame/SeekTo`, свойства `Media`, `Position`, `FrameIndex`
  и события `PositionChanged` / `StateChanged`. Ни WPF, ни FlyleafLib в нём не упоминаются —
  фаза 4 подставит сюда бэкенд на кэше кадров, не трогая UI.
- **`FlyleafBackend`** — реализация поверх FlyleafLib 3.10.4 с конфигурацией из спайка:
  точный seek, аппаратный декод D3D11, автозапуск и звук выключены.
- **`MediaInfo`** — кодек, разрешение, средняя частота, длительность, число кадров, флаг VFR;
  берётся у демуксера, а не у статистики воспроизведения (та на паузе нулевая).
- **Открытие файла**: диалог, перетаскивание в окно, аргумент командной строки
  (он же «Открыть с помощью» в проводнике).
- **Интерфейс**: кадр во всю ширину, таймкод и номер кадра поверх изображения,
  шкала позиции с делениями, транспорт, строка сообщений, панель сведений поверх кадра.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Space` | воспроизведение / пауза |
| `→` / `←` | шаг на кадр вперёд / назад (всегда ставит на паузу) |
| `Shift` + `→` / `←` | шаг на 10 кадров |
| `Home` / `End` | первый / последний кадр |
| `Ctrl` + `O` | открыть файл |
| `T` | таймкод поверх кадра |
| `I` | панель сведений |

## Решения по интерфейсу

- **Сведения — панель поверх кадра справа, по умолчанию свёрнутая** (кнопка «Сведения», клавиша `I`).
  В мокапе сравнивались статусная строка и постоянная колонка; выбран третий вариант —
  накладка, которая не отнимает ширину у изображения. Строка внизу осталась, но только под сообщения.
- **Таймкод поверх кадра включён по умолчанию**, состояние запоминается между запусками:
  при покадровой работе взгляд не отрывается от картинки.
- **Звука в фазе 1 нет.** Вопрос «чей звук при двух треках» решается в фазе 3.
- **Скраб шкалы декодирует один раз, по отпусканию кнопки.** Шаг назад на long-GOP занимает
  около секунды (замеры фазы 0), и seek на каждое движение мыши сделал бы перетаскивание неуправляемым.

## Технические заметки

- **Клавиатура ловится классовым обработчиком** `EventManager.RegisterClassHandler(typeof(Window), …)`.
  FlyleafHost выводит кадр в собственные окна (поверхность и накладка); когда фокус уходит туда,
  события до главного окна не доходят, и подписка только на него теряет часть нажатий.
- **Свои горячие клавиши FlyleafLib отключены** (`Config.Player.KeyBindings.Keys.Clear()`):
  библиотека перехватывала клавиши раньше приложения.
- **Первый кадр показывается сразу после открытия** (`ShowFrame(0)`): автозапуска нет,
  а чёрный прямоугольник читается как несработавшее открытие.
- **VFR определяется сравнением `r_frame_rate` и `avg_frame_rate`** у AVStream — точного флага
  в контейнере нет. При VFR номер кадра выводится с пометкой `≈`, потому что он вычисляется
  из времени, а не считывается.
- **FFmpeg** ищется по `COMPARISONPLAYER_FFMPEG_DIR`, затем в подкаталоге `FFmpeg` рядом с exe,
  затем в известных каталогах машины разработки. Без него приложение сообщает об этом и закрывается.

## Как запустить

```
dotnet build src/ComparisonPlayer/ComparisonPlayer.csproj -c Release
src/ComparisonPlayer/bin/Release/net9.0-windows/ComparisonPlayer.exe [путь-к-видео]
```

## Проверено

На `4k_h264_gop250.mp4` (3840×2160, 30 fps, 900 кадров):

- открытие аргументом командной строки, первый кадр на экране сразу;
- шаг вперёд: 3 нажатия `→` → кадр 3 (совпало с номером, впечатанным в тестовый ролик);
- `Shift` + `→` → +10 кадров (кадр 2 → 12);
- шаг назад возвращает ровно на исходный кадр;
- `End` → кадр 899, playhead в конце шкалы;
- воспроизведение по `Space`, шкала и таймкод идут;
- `I` открывает и сворачивает панель сведений, `T` переключает таймкод поверх кадра;
- неподдерживаемый файл: плеер остаётся в пустом состоянии и пишет причину в строку сообщений.

## Чего в фазе 1 нет

- Перетаскивание файла собрано, но проверялось вручную — автотеста на drag&drop нет.
- VFR-ветка не проверена на реальном ролике с переменной частотой: такого файла в тестовом наборе нет.
- При воспроизведении номер кадра может отставать на один: `CurTime` обновляется таймером
  с интервалом 100 мс. На паузе и при шаге номер точен — именно этот режим и важен.
- Шаг назад на long-GOP по-прежнему занимает около секунды: это закрывает фаза 4 (кэш кадров).
