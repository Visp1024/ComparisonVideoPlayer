# Задача #17 — вид при запуске и воспроизведение сразу при открытии

Плеер всегда открывался в виде «рядом» и всегда на паузе. Когда ролик открывают, чтобы
его посмотреть (двойной щелчок по файлу, «Открыть с помощью», перетаскивание), оба
умолчания мешают: сравнивать нечего, а воспроизведение приходится пускать руками.
Теперь вид при запуске выбирается в настройках, а воспроизведение начинается само.

## Что сделано

**Вид при запуске** ([settings-startup.png](task17-artifacts/settings-startup.png)) —
раздел настроек «Вид при запуске» с четырьмя значениями:

- «Как в прошлый раз» (умолчание) — вид приходит из восстановленной сессии, поведение
  прежнее;
- «Рядом», «Только A», «Только B» — выбранный вид ставится после восстановления сессии,
  то есть сильнее её.

Вид по-прежнему переключается на ходу клавишей `V`; настройка отвечает только за старт.

**Воспроизведение сразу при открытии файла** — флажок в «Общих», по умолчанию включён.
Срабатывает на открытие ролика: из диалога, перетаскиванием в окно и из командной
строки. Восстановление сессии остаётся на паузе: там возвращаются на прежний кадр, а не
смотрят ролик заново.

Проверка: запуск с роликом в командной строке при виде «Только A» —
[only-a-autoplay.png](task17-artifacts/only-a-autoplay.png): открыт один кадр во всю
ширину, транспорт показывает «пауза» (значит, идёт воспроизведение), playhead ушёл от
начала сам.

## Как устроено

- `Settings.cs` — `StartupLayoutMode` (`Remembered` / `Side` / `OnlyA` / `OnlyB`) и
  `StartupLayout`, плюс `AutoPlayOnOpen`. Тип отдельный от `LayoutMode`: у настройки есть
  значение «не навязывать», которого у самого вида нет.
- `MainWindow.xaml.cs` — `ApplyStartupLayout()` вызывается в конце `OnLoaded`, после
  открытия файлов командной строки и после `RestoreLastSession()`: иначе сессия перебила
  бы выбранный вид.
- `MainWindow.xaml.cs` — `AutoPlayAfterOpen()` у трёх точек открытия (диалог,
  перетаскивание, командная строка). Пуск откладывается фоновой очередью диспетчера:
  решение о кэше (`DecideCache`) меряет шаг назад точными переходами, и начатое до
  замера воспроизведение он всё равно сбил бы. К моменту пуска трек уже может играть из
  кэша — состояние воспроизведения смена движка сохраняет сама.
- `SettingsWindow.xaml[.cs]` — раздел «Вид при запуске» переключателями (как режим кэша)
  и флажок автостарта; «Сбросить по умолчанию» возвращает `Remembered` и включённый
  автостарт.

## Решения

- **«Как в прошлый раз» осталось умолчанием.** Сессия хранит вид с фазы 5, и жёсткое
  умолчание «рядом» молча сломало бы уже сложившуюся привычку. Кому нужен фиксированный
  вид — выбирает его явно.
- **Настройка сильнее сессии.** Обратный порядок означал бы, что выбранный вид работает
  только при пустой сессии, то есть почти никогда.
- **Автостарт — флажок, а не безусловное поведение.** При покадровом сравнении
  самопуск мешает, а отключить его должно быть можно без правки файла настроек.
- **Восстановленная сессия не играет.** Сессия — это возврат к рабочему месту: позиция,
  сдвиг и отрезки. Пуск с восстановленного кадра увёл бы playhead с него сразу же.
